# 와이퍼넷 (WiperNet)

> 도로 위 현대차들의 와이퍼 작동 정보를 익명으로 모아, 경로 앞 **지하차도 침수 위험을 미리 경고하고 우회를 권하며**, 비 구간에 들어가기 전에 **차를 미리 준비시키는** Pleos Connect 차량용 앱.

2026 현대자동차그룹 차량용 앱 개발 공모전 출품작입니다. 기능별 상태와 에뮬레이터 확인 결과는 [기능지도](docs/features/README.md)에 있습니다.

---

## 바로 실행해 보기 (심사위원용)

서버 없이 APK만 설치해도 **데모 모드**로 2022-08-08 강남 폭우 속 주행이 처음부터 끝까지 재생됩니다.

| 항목 | 내용 |
|---|---|
| APK | [`apk/김태건_WiperNet_release.apk`](apk/) |
| 개발·테스트 에뮬레이터 | Pleos Connect Emulator v2.1.0 (시스템 이미지 "Pleos Connect v2.1.0 APIs arm64", Android 14 / API 34), Cold boot, RAM 4 GB |
| 화면 규격 | 2560 × 1440 (에뮬레이터 기본) |
| 앱 최소 버전 | Android API 28 |
| 필요한 설정 | 없음. 첫 실행 때 동의 화면에서 "동의"를 누르면 데모 모드로 시작합니다. 알림·마이크 권한을 물으면 허용해 주세요 |
| 함께 열면 좋은 것 | Pleos Connect Virtual Console (`adb forward tcp:8088 tcp:8088` 뒤 http://127.0.0.1:8088/). 브라우저에 열려 있어야 창문·김서림 방지·전조등 제어가 실제로 반영됩니다. 닫혀 있으면 앱이 음성으로 대신 권합니다 |

### 설치와 실행

```bash
adb install -r apk/김태건_WiperNet_release.apk
```

1. 에뮬레이터에서 와이퍼넷을 엽니다.
2. 동의 화면에서 **동의**를 누릅니다. 알림과 마이크 권한은 허용합니다.
3. 데모가 시작됩니다. 와이퍼넷 화면은 닫아도 되고, 홈이나 내비를 띄워 두어도 뒤에서 계속 돕니다.

| 시작 뒤 | 일어나는 일 |
|---|---|
| 약 30초 | "곧 비 구간이에요." 차량 준비: 창문 닫기, 김서림 방지, 전조등 |
| 약 140초 | "곧 더 강한 비 구간이에요." (이미 된 항목은 다시 말하지 않습니다) |
| 약 210초 | 경로 앞 개포지하차도 2.0 km 경고(음성, 알림, 앱 화면 위쪽 주황 띠)와 "우회 경로로 안내할까요?" |
| 질문 뒤 | "응·네·예"로 답하거나, 알림 창의 **예** 버튼을 누르면 우회 경로로 바뀝니다. 답하지 않으면 원래 경로로 가다가 약 420초에 "위험" 단계로 다시 경고합니다 |
| 약 9.5분 | 도착해 주차(기어 P)합니다. 앱 화면의 **비 지도** 버튼으로 내 주변 3 km의 비와 지하차도 위험을 봅니다 |

앱 화면의 **데모 처음부터** 버튼으로 언제든 다시 시작합니다. 앱 설정 아래 "시연·개발용"에서 데모와 라이브 모드를 바꿉니다.

> 참고: Pleos는 앱 알림을 화면에 팝업으로 띄우지 않고 알림 창에만 넣습니다. 우회 질문의 예/아니오 버튼은 알림 창을 내려서 누릅니다.

## 해결하려는 문제

- 2023-07-15 오송 궁평2지하차도 침수로 14명이 숨졌습니다.
- 감사원 조사(2024)에서 전국 지하차도 1,086곳 중 182곳이 침수 우려가 크고, 132곳에는 진입 차단시설이 없었습니다.
- 진입 차단시설은 **이미 물이 찬 뒤** 작동합니다. 와이퍼넷은 그 전에, 운전자가 지하차도 쪽 경로로 들어서기 전에 알려 줍니다.

한국 내수 시장에서 현대차그룹 차량 비중은 약 90%입니다. 와이퍼를 켠 차가 많을수록 비 지도가 촘촘해지고, 경고가 정확해집니다.

## 주요 기능

1. **지하차도 침수 경고 + 우회 권유**: Pleos 내비 길안내 경로의 안내 지점에서 "지하차도 진입"을 찾아, 내 경로 위 지하차도 주변에서 여러 차가 폭우를 감지하면 음성과 알림으로 알립니다. 동의하면 그 내비 경로에 우회 지점을 경유지로 넣습니다. 길안내를 하지 않을 때는 진행 방향 앞의 지하차도를 봅니다.
2. **비 구간 진입 전 차량 준비**: 창문 닫기, 김서림 방지, 전조등 켜기를 Pleos Vehicle SDK로 직접 제어하고, 실제로 바뀌었는지 다시 읽어 확인합니다. 안 바뀐 항목은 음성으로 권합니다.
3. **음성으로 묻고 답하기**: 우회 질문에 음성(STT)이나 알림 버튼으로 답합니다. 주의 안내 뒤 "그만"이라고 하면 주의 단계 안내를 끕니다(위험 단계는 계속 알림).
4. **비 지도**: 기어 P에서 내 주변 3 km의 비 세기와 위험 지하차도를 보여 줍니다.

와이퍼넷은 열어서 쓰는 앱이 아니라 **뒤에서 도는 앱**입니다. 처음 한 번 동의하면 포그라운드 서비스로 계속 돌고, 재부팅 뒤에도 저절로 시작합니다. 위험할 때도 앱 화면을 강제로 띄우지 않아 내비를 가리지 않습니다.

## 구조

```
┌────────────────────┐      같은 API      ┌──────────────────────┐
│ 가상 차량 시뮬레이터 │ ───────────────▶ │                      │
│ (수백~수천 대,       │   와이퍼 이벤트    │        서버          │
│  2022-08-08 재현)   │                   │  격자 비 지도 집계    │
└────────────────────┘                   │  지하차도 위험 단계   │
                                          │  + 특보·재난문자·레이더 │
┌────────────────────┐  와이퍼 이벤트 ──▶ │                      │
│ 차량 앱 (에뮬레이터) │ ◀── 위험 정보 ─── │                      │
│ 경고 · 우회 · 준비  │                   └──────────────────────┘
└────────────────────┘
```

- 시뮬레이터와 차량 앱은 **같은 서버 API**로 데이터를 보냅니다. 서버 입장에서는 가상 차와 실제 차가 구분되지 않습니다.
- 세기 추정, 격자 집계, 위험 판단은 서버 한 곳에서만 합니다. 기상청 호우특보, 재난문자, 레이더는 위험을 올리기만 하고 내리지 않습니다.
- 차량 ID는 12~18분 사이 무작위 간격으로 바뀌는 임시 ID입니다. 출발지와 목적지 300 m 안에서는 보내지 않고, 서버는 원시 이벤트를 2시간까지만 보관합니다.

| 폴더 | 내용 | 기술 |
|---|---|---|
| `backend/wipernet_server` | 서버, 시뮬레이션 뷰어(`/viewer`) | Python 3.12, FastAPI |
| `backend/wipernet_sim` | 가상 차량 시뮬레이터, 검증, 데모 시나리오 만들기 | Python, osmnx |
| `car-app/` | Pleos 차량 앱 | Kotlin, Jetpack Compose, Pleos Connect SDK |
| `apk/` | 제출용 APK | |
| `docs/` | 설계, [API 계약](docs/api.md), [기능지도](docs/features/README.md), [검증 리포트](docs/validation.md), [SDK·에뮬레이터 확인 기록](docs/setup-status.md) | |

사용하는 Pleos SDK: Vehicle(와이퍼·기어·창문 읽기, 창문·공조·조명 제어), NaviHelper(길안내 상태·안내 지점·경유지), FusedLocation(위치), TextToSpeech(음성 안내), SpeechToText(음성 응답).

## 전체 시스템 실행 (개발자용, 라이브 모드)

라이브 모드는 서버, 시뮬레이터, 에뮬레이터를 한 Mac에서 함께 돌립니다.

### 1. 서버

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/uvicorn wipernet_server.api:app --host 0.0.0.0 --port 8000
```

외부 자료는 기본으로 2022-08-08 기록을 재생합니다(`WIPERNET_EXTERNAL=replay`). 실시간 기상청 자료는 `WIPERNET_EXTERNAL=live`와 `backend/.env`의 `KMA_API_HUBKEY`가 필요합니다.

### 2. 시뮬레이터와 뷰어

```bash
cd backend
.venv/bin/python -m wipernet_sim.runner --density future --speed 60
```

- `--density current|future`: 현재(약 140대) 또는 미래(약 2,100대) 차량 밀도.
- 내 차(앱)와 함께 볼 때는 `--slow-from 17:44 --slow-speed 1`로 그 시각부터 1배속으로 늦춥니다.
- 브라우저에서 http://127.0.0.1:8000/viewer 를 열면 가상 차량, 비 지도, 지하차도 위험 단계가 실시간으로 보입니다.

### 3. 차량 앱

```bash
cd car-app
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

앱 설정의 "시연·개발용"에서 모드를 **라이브**로 바꾸면 서버(기본 `http://10.0.2.2:8000`)에 연결합니다. Pleos 내비에서 목적지를 넣고 길안내를 시작하면 앱이 그 경로를 읽습니다. Virtual Console에서 와이퍼를 바꾸면 뷰어에 내 차가 나타납니다. 이벤트 시각은 기기 시각이 아니라 서버 시계(시뮬레이터가 재생하는 시각)를 쓰므로, 시뮬레이터를 먼저 켭니다.

### 테스트

```bash
cd backend && .venv/bin/pytest -v
cd car-app && ./gradlew test
```

## 검증

전체 결과는 [`docs/validation.md`](docs/validation.md)에 있습니다(2022-08-08 17:00~23:00, 시드 1).

- **와이퍼만으로 비 지도 복원:** 현재 밀도(지역 안 100대)는 비 감지 적중률 54%, 오경보율 7%. 미래 밀도(1,500대)는 적중률 91%, 오경보율 8%, 오차 4.4 mm/h.
- **관측소만으로는 부족하다:** 데모 지역의 유일한 AWS인 서초 관측소를 빼고 주변 관측소로 메우면, 20~21시 비를 92.0 mm/h가 아니라 56.4 mm/h로 추정합니다. 관측소 사이를 촘촘히 재는 수단이 필요한 근거입니다.
- **지하차도 경고 시각:** 개포지하차도는 실제로 21:00~21:30께 통제됐습니다(보도). 와이퍼와 외부 자료를 합친 서버는 17:51에 "위험"을 냈습니다. 통제 시각은 정답이 아니라, 경고가 실제 통제보다 늦지 않았는지만 보여 줍니다.

시뮬레이터 차는 기상청 AWS 관측값으로 만든 강우장으로 와이퍼를 돌립니다. 그래서 이 검증은 "서버가 와이퍼 신호로 비 지도를 얼마나 복원하는가"를 보여 주고, "실제 와이퍼가 비를 맞힌다"는 증명하지 않습니다.

## 한계와 가정

- 실차에서 검증하지 않았습니다. 모든 시연은 Pleos Connect Emulator에서 합니다.
- 에뮬레이터 내비의 현재 위치가 고정이라, 라이브 모드에서 차가 경로를 따라 지하차도에 다가가며 경고하는 장면은 데모 모드(녹화 시나리오 재생)로 보여 줍니다. 길안내 상태·안내 지점 읽기와 경유지 추가는 에뮬레이터에서 확인했습니다.
- 우회 지점 하나를 경유지로 넣는 방식이라, 내비가 다른 지하차도를 지나거나 유턴하는 경로를 고를 수 있습니다. 위험 지하차도를 지나면 그 지하차도에 다가갈 때 다시 경고합니다.
- 와이퍼 AUTO 모드에서는 세기를 알 수 없어, 최근 1분 와이퍼 횟수로 추정합니다. 이 추정식은 검증하지 않은 가정입니다.
- 차량 밀도(현재 100대, 미래 1,500대), AUTO 비율, 운전자 반응은 가정치입니다.
- 이날 레이더는 센 비를 AWS의 약 40%로 적게 잡습니다. 레이더는 보조로만 씁니다.
- 공모전 시연용 서버는 메모리에만 데이터를 둡니다. 실제 운영에는 DB와 서버 호스팅이 필요합니다.
- 실제 App Market 배포에는 Vehicle SDK 권한 협의와 위치기반서비스사업 신고가 필요합니다.
